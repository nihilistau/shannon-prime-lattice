## 1. Seam analysis — three findings from the 2026-06-09 survey (read before coding)

The survey of `core/forward/decode.c` + `core/arm/arm.c` + `include/sp/arm.h` surfaced three architecture facts that reshape C1-lite's first slice. None were obvious; all are load-bearing.

1. **The two-ring is per-decode-EPHEMERAL.** `qwen3_generate_kv` / `qwen3_ppl_decode` build the recall index `projk` (`[NL × P × NKV × r]` f32) and the Ring-2 store *fresh inside the call* and `free()` them at `done:`. There is **no persisted episode object** for a curator to sit between. The curator's whole premise — operate on stored state between sessions — has no seam yet. *This is exactly RFC §7's "episode persistence" item, now confirmed as a prerequisite, not an add-on.*

2. **`projk` is RECOMPUTABLE from the persisted K store.** The router index is just the frozen ±1 Rademacher projection of each position's post-RoPE K (`sp_arm_project`). The Ring-2 K stream (the stdio backend's `sp_arm_ring2_k.bin`) already persists that K. So episode persistence does **not** need to serialize `projk` — it can be rebuilt by re-projecting the stored K on load. Persisted episode = {K store, V store, manifest} + a re-projection pass.

3. **Eviction is DOUBLY entangled, and the stdio store TRUNCATES on open.** (a) Dropping a block from the Ring-2 store alone does not change recall — the router selects by `projk` score over all positions independently; a curator that evicts must prune *both* the store and the `projk` index (or the rebuilt-from-store index, which makes #2 the clean path). (b) `sp_arm_ring2_stdio_open` uses `fopen(..., "w+b")` — "fresh store per open" — so the current decode **cannot load a pre-curated store**; replaying a curated episode needs a non-truncating load path or a registered backend that serves curated data.

**Net:** C1-lite's enabling capability is an **episode replay decode mode** (load persisted K/V + rebuild `projk` + score a window against it). The curator + gate compose on top of that. The cleverness (which heuristic) is downstream of the plumbing (can we replay a foreign episode at all).

## 3. Gate currency & receipts

PPL via `qwen3_ppl_decode` (teacher-forced, the C2.1 instrument). Episode size = stored position count × per-position bytes. Every promotion logs a receipt: positions evicted/merged, before/after PPL + size, accept/reject reason — the auditable-dream record (RFC §6). Model: the proven `qwen3_rt.sp-model` (OK_Q8 swivel). Honest bound carried from C2: Spinor-KV recall is a ~6.5%-argmax-flip lossy overlay, so the replay null gate is bounded-divergence, not bit-exact (the weight path + recall-off remains the bit-exact floor).

## 3a. C1L.0b Step 2 — the decode.c replay surgery (landed 2026-06-09, gate run pending on the canonical build)

The non-truncating `_ro` seam is now wired into the canonical decode (`core/forward/decode.c`, `generate_kv_impl` — shared by `qwen3_generate_kv` and `qwen3_ppl_decode`). Five **gated, off-path-inert** edits:

1. Globals `g_replay` / `g_replay_dir` / `g_replay_npos` (default 0/"."/0).
2. Env reads `SP_REPLAY` / `SP_REPLAY_DIR` / `SP_REPLAY_NPOS` in `read_env_knobs`.
3. A `replay_be` backend opened via `sp_arm_ring2_stdio_open_ro` just before the position loop — **admissible only on the plain f32 path** (`!use_blocks && !fusion_on`); inadmissible configs leave `replay_on=0`.
4. The injection: immediately after the per-head RoPE and **before** the projk build, for `pos < g_replay_npos` the computed post-RoPE `knew`/`vnew` are overwritten by episode block `(L,pos)` at byte `((L*P)+pos)*KVD*sizeof(float)` (the ring2 stdio spill layout). Everything downstream — `projk`, the Ring-1/2 cache, the spill, attention — then consumes the loaded history. The live query `q` is **not** replaced.
5. `done:` closes the owned `replay_be`.

**Off-path floor:** `SP_REPLAY` unset → the branch is never entered, zero allocations, byte-for-byte the prior canonical forward (the bit-exact replay-off guarantee). The Linux sandbox compiler parsed through all five edit sites without error (the only failures were the workspace mount truncating decode.c's tail + a stale-arm.h artifact — tooling, not code; see [[feedback-workspace-mount-stale-partial]]). The math-core CPU path is **Windows MinGW (build/)** + the real `qwen3_rt.sp-model`, so the gate runs there, not in the sandbox.

**G-C1L-0b Step 2 (decode-layer replay null): PASS 2026-06-09** — in-tree gate `T_GENKV_REPLAY_NULL` added to `core/session/arm_genkv_gate.c` (the T_ARM_GENKV harness; synthetic qwen3 fixture, HD=8, decodes through the canonical `qwen3_generate_kv`). Built on the canonical Windows MinGW (gcc 15.2, ninja; libsp_arm.a + libsp_forward.a relinked) — **34/34 checks, 0 fails**. CAPTURE spills the full 28-position episode to `epcap/` (== baseline). REPLAY-INTACT (`SP_REPLAY=1 SP_REPLAY_DIR=epcap SP_REPLAY_NPOS=28`, ring/recall off) overwrites every position's post-RoPE K/V from the `_ro`-loaded episode → **top-1 sequence byte-identical to baseline** (the loaded K/V flow losslessly through projk + the f32 cache + attention; stronger than the PPL-within-Spinor-bound the gate asked for — the stdio store is f32-exact so replay is bit-exact). NEGATIVE control (zeroed `epcap/*.bin`) **DIVERGES** (`…34 13 41 34 13 41…` degenerate loop vs baseline `…34 34 13 32 34 19 13…`), proving the loaded bytes drive attention. The other 10 gates run `SP_REPLAY=0` → the canonical forward is **bit-exact (replay-off floor confirmed)**. Recall-layer (Step 1) + load seam + model-attention layer (Step 2) all green ⇒ **C1L.0b CLOSED**; episode replay is the enabling capability for the curator loop (C1L.1 already green) + cold-evict (C1L.2).

Original turnkey procedure (now executed; retained for the real-`qwen3_rt.sp-model` reproduction):

- **CAPTURE** (writes the episode + records PPL_A): `SP_RECALL_B=<B> SP_RECALL_W=<W> SP_RING2=1 SP_RING2_DISK=1 SP_RING2_DIR=ep` → `ep/{sp_arm_ring2_k.bin,sp_arm_ring2_v.bin}` persisted, PPL_A reported.
- **REPLAY (intact)**: same recall/ring2 config (spilling to a fresh `ep2`) **plus** `SP_REPLAY=1 SP_REPLAY_DIR=ep SP_REPLAY_NPOS=<P>` → historical K/V overwritten by the loaded (bit-identical) episode → **expect PPL_replay == PPL_A bit-identical** (the f32 stdio store is lossless; the Spinor bound only applies to a Spinor-coded episode). This proves the load+inject seam routes disk bytes faithfully into the live K/V attention consumes — without corruption.
- **NEGATIVE CONTROL (zeroed episode)**: `dd if=/dev/zero` over `ep/*.bin` (or a curator-perturbed copy), replay again → **expect PPL materially worse** → proves the loaded bytes actually drive attention (replay is not a silent no-op).
- **CONTROL (replay-off)**: drop `SP_REPLAY` → PPL byte-identical to the no-replay baseline (the floor).

Intact-faithful + zeroed-divergent + off-identical is the honest decode-layer analog of the Step-1 standalone null already passed. Recall-layer + load-seam already green (§C1L.0b Step 1); this closes the model-attention layer.

## 4. Scope discipline

C1-lite proves the curator's **control flow + a working heuristic on real KV**, nothing about learned compression (that is C2 = the P2.b adapter applied to ring state). It runs entirely on the qwen3 CPU path; the gemma4-CUDA ring is P3. NIGHTSHIFT (N1) = C1-lite's loop run offline under schtasks over a persisted episode — so C1L.0's persistence format is also NIGHTSHIFT's episode format. No silent gate revisions; surface upstream.
