## 1. Scope & non-goals

**P3 is the ring WIRING on the Exec, nothing else.** The Exec path is `gemma4_decode_cuda` (`shannon-prime-system-engine/src/backends/cuda/cuda_forward.cu:1634`), the ETA.5a/5b decode with the jagged per-owner KV cache. The reference being ported is the qwen3 CPU wiring in `core/forward/decode.c` (projk sidecar build at decode.c:470-480, `sp_arm_select` sites at decode.c:608-623, Ring-2 spill setup at decode.c:339-391, `SP_REPLAY` injection at decode.c:457-468) — that path is the PATTERN and stays UNMODIFIED. The geom substrate is already landed and gated (core `64b698c`: `sp_arm_geom` descriptor + `sp_arm_geom_layout` + `sp_arm_project{,_sig}_geom` / `sp_arm_select{,_sig}_geom`, `include/sp/arm.h:129-192`; legacy entry points delegate, uniform-null bit-exact, T_ARM_GEOM 26/26). P3 consumes that API; it does not extend it.

**Substrate precondition.** Development runs against the **12B B1 artifact** (OK_Q4B per-32, the 06-R10 gold instrument: 24/24 gates, PPL 5.12, 26.1 tok/s on the 2060-12GB) as the Exec, and the **E2B** artifact for cheap gates wherever a stage doesn't need 12B-class capacity. The two artifacts split the gate load by construction:

- **12B** (NL=48, period 6 → 8 global / 40 SWA; CONTRACT-XBAR-P1 §1): every layer owns its K/V (the dense artifact carries no shared-KV; P1's CAPTURE of all 48 per-layer rows is the receipt). The 12B exercises **G-P3-GEOM** (jagged classes, V-less globals) at real capacity.
- **E2B** (NL=35, period 5, **kvfs=15** → 15 owners / 20 sharers; SESSION-CLOSED-stage-eta-phase1 finding 3-4): the only artifact in hand with real sharer layers. The E2B exercises **G-P3-SHARED** (owner-indirection, owner-map manifest) cheaply.

Every run banner echoes its geometry from the loaded config (`kvfs`/`period`/per-class dims), never from prose — the banner-echoes-getenv rule extends to geometry.

**Non-goals (each owned elsewhere):**
- NOT the trained Memo / learned curator — that is C2 (the P2.b adapter lane), currently adapter-limited per the k-sweep verdict.
- NOT NIGHTSHIFT (N1) — the offline schtasks loop composes on P3's persisted episodes but is its own contract.
- NOT multi-writer permissions on Ring 2/2′ — the RFC §8 named gap stays open; Exec is the sole writer here.
- NOT Spinor-lossy KV on the Exec — v0 rings carry the f32 cache bytes (the CUDA cache is f32; the Spinor overlay is a later, separately-gated knob, as it was on qwen3).
- NOT G-P3-WIN (ring-window × model-SWA interaction, global-vs-SWA recall policy) — explicitly DEFERRED to a follow-on stage after P3.4; v0 recall treats the budget uniformly per layer and the SWA window stays the model's own (audit row #4 stands as an open, lower-risk item).
- NOT CUDA-graph-path ring execution — see §4 risk 1; v0 ring work lives on the per-step path only.

### P3.0 manifest schema (normative)

Episode = `{K store, V store, manifest}` (the C1-lite/N1 format, extended). Manifest fields:

- header: magic/version, artifact sha, projection seed version (`SP_ARM_PROJ_SEED`, arm.h:47-49), `NL`, `P`, `period`, `kvfs`, `r`;
- per-layer record `[NL]`: `class` (GLOBAL/SWA), `nh`, `nkv`, `hd`, `kvd = nkv*hd`, `rope_base`, `has_freq_factors`, `window` (−1 global / SW), `owns_kv = (L < kvfs)`, `own[L]` (= `L` for owners; `kvfs−1` global / `kvfs−2` SWA for sharers — gemma4.c:198-202, bounds-guarded core `c608b2f`), `vless` (attn_v absent ⇒ V = weightless-normed raw K proj — gemma4.c:179-187), `off[L]` (per-owner episode byte offset, prefix-sum law in §3).

projk is NOT serialized — rebuilt by re-projection from the stored K (the C1L.0a proven property), now via `sp_arm_project_geom` per class.

### Host-vs-device router: the v0 decision (recommended: HOST)

Post-RoPE K exists only on DEVICE: the per-step path mints `dk` → `k_rmsnorm_head` → `k_rope_*` → `cudaMemcpyAsync` into `dKc[L]` (cuda_forward.cu:2147-2155); the graph path uses `k_kv_store` with device `dpos` (cuda_forward.cu:1959). Two ways to get a router:

- **HOST v0 (chosen):** D2H the minted K (and the roped q) per step, project + select with the SAME `core/arm` code the CPU gates already proved (T_ARM_GEOM 26/26) — zero new router math, the CPU oracle is the parity twin for free. Cost: K = 48·512·4 B ≈ 96 KiB + q ≈ 48·2048·4 B ≈ 384 KiB ⇒ ~480 KiB/step D2H + per-step syncs ≈ low-ms; against the 12B's 38.3 ms/step (26.1 tok/s, 06-R10) that is a single-digit-% v0 tax on a gate lane. Per-step path only.
- **DEVICE (deferred):** a `k_arm_project` kernel + device top-k. New CUDA math ⇒ needs its own exactness gate (identical cand arrays, the `sp_arm_scan_sig` override contract, arm.h:117-127). This is the perf pass, not the correctness pass; do it only after G-P3-PPL is green host-side.

## 3. Geometry law (the §3b audit table, normative form)

Ground truth, line-cited: per-layer class `global = (L % period == period−1)` (gemma4.c:148, cuda_forward.cu:2130); 12B GLOBAL = nh 4 / **nkv 1 / hd 512**, RoPE 1e6 + proportional freqs, full attention; SWA = nh 8 / **nkv 2 / hd 256**, RoPE 1e4, sliding window (gemma4.c:70-71,149-157; CONTRACT-XBAR-P1 §1). Owners `[0,kvfs)`; sharers reuse `kvfs−1` (global) / `kvfs−2` (SWA) and mint nothing (gemma4.c:174,197-204; cuda_forward.cu:2146-2160).

| Transfers **as-is** (12B) | Is **per-class** (manifest-carried) | Is **owner-indirect** (sharer layers) |
|---|---|---|
| Episode block layout `((L*P)+pos)*KVD*4` with **KVD = 512 constant** (global 1×512 = SWA 2×256; gemma4.c:16,79 — audit finding #1). The `SP_REPLAY` injection discipline (overwrite minted K/V pre-store, post-RoPE, query untouched). The Rademacher R built once at `hd_max = 512` (the arm.h:139-145 R-sizing contract). | projk strides + offsets (`sp_arm_geom_layout`, heterogeneous per-layer blocks `P*nkv*r`); select NKV/HD per class (`sp_arm_select_geom` descriptor); RoPE base + freq-factors and the attention window (capture metadata — needed to interpret an episode, not to address it). | **Spill**: sharers write nothing (skiplist). **Recall**: reads address `own[L]`'s store/projk block. **Replay**: injects owner rows only; sharer attention follows because `Kuse/Vuse` alias the owner buffer by construction. |

**The E2B caveat (new in this contract — the constant-KVD layout does NOT transfer there):** the jagged cache is genuinely jagged on the E2B — global owners write 512-wide rows, SWA owners 256-wide (cuda_forward.cu:1615-1617, alloc at 1817-1822 computes `kvd` per class). The normative episode addressing is therefore the **prefix-sum law**:

```
off[L]            = Σ_{L' < L, owns_kv(L')} P · kvd_{L'} · 4      (owners only)
block(L, pos) at    off[own[L]] + pos · kvd_{own[L]} · 4
```

On the 12B (all owners, kvd ≡ 512) this degenerates exactly to `((L*P)+pos)*512*4` — the C1-lite layout, byte for byte. P3.0's gate holds the degeneration as the uniform-null.

### projk sidecar sizing (computed from the real 12B dims)

Per-layer f32 projk block = `P·nkv·r` floats (arm.h:147-154). 12B: Σ_L nkv = 8 global·1 + 40 SWA·2 = **88** kv-head streams ⇒ total = `88·P·r` floats = `352·P·r` bytes:

| P | r=32 | r=64 |
|---|---|---|
| 2048 | 352·2048·32 = 23,068,672 B ≈ **22.0 MiB** | 44.0 MiB |
| 4096 | 46,137,344 B ≈ **44.0 MiB** | 88.0 MiB |
| 8192 | 92,274,688 B ≈ **88.0 MiB** | 176.0 MiB |

Sig (bit-packed) sidecar = `88·P·8` B = 704·P: 1.4 / 2.8 / 5.5 MiB at the same P — the gated lossier overlay, same admission rule as ever (re-pass NIAH + deflection per regime). v0 keeps projk HOST-side (router decision above), so this is RAM, not VRAM; if the device router lands later the same bytes move on-card and remain negligible against the cache (next).

### P3.1 decode-wiring (normative — the byte law locked BEFORE the C is cut, 2026-06-12)

**Seam (NOT PagedAttention — this is a flat statically-allocated cache).** No block-table, no logical→physical page map. The decode attention reads `Kc + pos·KVD + kvh·HD` from a per-layer base (`k_attn_decode_win` cuda_forward.cu:246; `k_attn_decode`/`_dyn` already take a `layer_off` byte param @ :433/:2744). P3.1 redirects **only the per-layer base + `layer_off`** in the decode loop's pointer setup (~cuda_forward.cu:1878-2170), behind an `xbar_active` flag: `Kc/Vc ← xbar_base`, `layer_off ← d_off[L]`. **Read path only** — generation queries the past, never mutates it (write/consolidation = P3.2).

**The byte law (f32, owner-resolved at build).** `KV_Addr = xbar_base + off[L] + pos · kvd_L · 4`, where `off[L] = layers[L].off` (already `= off[own[L]]`, prefix-sum + owner-indirection collapsed at `sp_xbar_manifest_build`; xbar_episode.h:79,103-105) and `kvd_L = layers[L].kvd`. Store is **f32 — the `·4` is baked into `sp_xbar_block_off`**; the kernel must NOT re-apply `sizeof(dtype)`. `own[L]` is NEVER dereferenced on-device.

**Device mount (one copy at episode-load; no per-step host ping).** `xbar_mount_episode(mf)` uploads two flat arrays `off[NL]` (int64) + `kvd[NL]` (int32) — ~576 B for NL=48 — once. No 3D `[layer][episode][pos]` map (v0 mounts ONE episode); no runtime owner-chase. `xbar_unmount` clears the flag.

**Gate G-P3-1 — BIT-EXACT (`max_abs_err == 0.0`), laddered.** Pure base-pointer redirect ⇒ identical kernel + identical reduction order ⇒ bitwise-identical logits (NOT `1e-5`; that tolerance is only for reduction-order changes, which P3.1 has none). Extract a context's K/V to an episode store (curator/replay path), clear the live cache, decode the same prompt with `xbar_active` → logits bit-match the legacy decode. **LADDER:** (1) **12B uniform-null** first (all owners, kvd≡512, law degenerates to `((L·P)+pos)·512·4` — isolates wiring from jaggedness; extends the P3.0 uniform-null one layer into decode); (2) **E2B jagged** (512/256 owner-indirection). The gate set MUST include a **global (v-less) layer** so the V-stream (raw-K provenance, Risk #5) is verified, and per Risk #6 a 12B-only green is NOT shared-KV-ready. Knobs-off must re-green BOTH paths bit-exact (Risk #1: `xbar_active` ⇒ graph declines).

**Dependencies (queue).** P3.1 → **P3.1b** needle-on-real-prompts (unblocked: #115 tokenizer parity 5432/5432 closed; 12B text-in needs gold-blob `--tok-only` regen) → **P3.2** write/consolidation wiring (the inverse: spill stale live-cache blocks into the episode store on overflow) → **P3.2b** Ring-1 shrink (32k). projk stays host-side (VRAM-neutral). KAIROS recall policy (cue→episode_id, incl. the P2.b §3q top-5 shortlist→verify two-stage loop) is the Python orchestrator ABOVE this substrate — separate layer, separate gate.

**G-P3-1b-2 RUN-RECORD — recall-as-history BIT-EXACT GREEN (2026-06-12, real 12B). THE READ-PATH IS COMPLETE.** `SP_XBAR_RECALL_HISTORY=dir` + `SP_XBAR_HIST_H=H`: pre-load the episode's first H positions' K/V into the FRONT of the live cache `[0,H)` (owners only; sharers reuse), and `continue` the decode loop over `pos < H` (episode forward skipped). **The cleanest construction needs NO offset threading** — `pos` is already absolute in the non-graph path (RoPE/cache-write/`ctx`=pos+1), so the prompt at `[H,..)` and the prepended episode at `[0,H)` fall out for free; the attention spans `[episode ++ prompt]` over the single contiguous cache. **THE BUG + FIX (the unforgiving one, caught by diagnostic not by reasoning):** the 12B packed embed indexes `dseq[*dpos]` (device counter), and `dpos` is advanced only by `k_incr_pos` at the loop end — which the `continue` skip bypassed, so `dpos` ran **H behind** (`pos=2 dpos=0` → embedded the dummy episode-slot token, decode fed wrong tokens; first matches were coincidental). FIX = **seed `dpos = H`** (one line) so increments keep `dpos == pos`; also `use_graph &&= !xbar_hist_on`. Gate (in-process, `test_gemma4_cuda.c`): monolithic `[episode{2,10}++prompt{100,1000}]` decode vs WRITE-episode→HISTORY-decode-prompt → **continuation token-identical, diffs[2..16)=0** (`...497 564 101 101 236855 45518 5015 ...` in both); diag confirmed `dpos==pos` post-fix. **Read-path ladder COMPLETE + bit-exact on the 12B at every rung:** P3.1 (off[L] mirror read) → P3.1b-1 (serialized episode from disk) → P3.1b-2 (prepended episode as history). **NEXT = P3.2 write/consolidation** (spill stale live-cache blocks into the episode store on overflow — the inverse of the read-path) → P3.2b Ring-1 shrink. KAIROS recall policy (cue→episode, §3q two-stage retrieve-verify) is the orchestrator above this now-complete read substrate.

**G-P3-R2.a RUN-RECORD — shadow spill BYTE-EXACT GREEN (2026-06-12, real 12B). WRITE-PATH STARTED.** The inverse of the read-path: `SP_XBAR_SPILL=dir` opens the Ring-2 store via the **registered-backend ABI** (`sp_arm_ring2_stdio_open`, `w+b` — the same `sp_arm_ring2_backend` the CPU `decode.c` Ring-2 spill uses; no new format) and computes `spill_off[L]` with the §3 owner prefix-sum. **Per step, AFTER the layer loop has written `dKc/dVc[L][pos]` for every owner**, all owner rows for `pos` are batched-async-D2H'd into ONE pinned staging buffer, **ONE** `cudaStreamSynchronize`, then `write_block(which, off[L]+pos·kvd·4, …)` owners-only (sharers reuse the owner block and spill nothing — **0 sharer blocks in store**). Identity is structural: the spill copies the authoritative cache bytes post-sync, so sync-vs-async is irrelevant to identity (the one-staging-buffer/one-sync batching is the §4 Risk-#3 guidance, a perf choice not a correctness one). **GATE** (`download:`, in-engine): read every spilled owner block back via `read_block` and `memcmp` vs a fresh D2H of the final live `dKc/dVc[L][0..P-1)`. Result on `gemma4-12b.sp-model` (48 owners, 0 sharers, JAGGED kvd global-512/SWA-2048): **diffs=0 at the DEC gate (P=16, 15 positions, store 5.2 MiB) AND the 256-token velocity decode (259 positions, store 85.3 MiB), three independent decodes all PASS**, `TEST_EXIT=0`, no leaked process. Store file length = `store_bytes − (last owner's unwritten P-1 slot, 2048 B)` exactly — independently confirms the "loop mints `[0,P-1)`" byte law. **CAVEAT (perf, not correctness):** the per-step synchronous spill serializes the longer velocity decode (GPU idles between steps while the D2H+write_block I/O runs) — the pinned-overlap optimization is the P3.2 perf follow-on, deferred behind the null/identity-first gate exactly as the read-path was. Engine `cuda_forward.cu` (open + per-step spill + byte-identity gate + cleanup, all behind `SP_XBAR_SPILL`, byte-inert off), built VS2022/VS18 host.

**G-P3-R2.b-1 RUN-RECORD — paged-read BIT-EXACT GREEN (2026-06-12, real 12B). THE CLOSED LOOP RUNS.** `SP_XBAR_PAGE=dir` (implies spill). The per-step closed loop, live: **(1) page-in** — at the top of the per-pos loop, restore `[0,pos)` for every owner from the Ring-2 store (`read_block(off[L], pos·kvd·4)` — `[0,pos)` is contiguous within owner L's region → ONE read + ONE H2D per owner, synced) into the live cache; **(2)** layer loop writes `pos` live + attention reads `[0,pos]`; **(3) spill** `pos` (P3.2-a); **(4) POISON** — `cudaMemset(0)` `[0,pos]` in the live cache so the NEXT step is forced to page it back. The poison is the rigor: it guarantees the live cache cannot be the attention source, so a bit-identical output proves every read was served off disk through `off[L]`. **GATE** (in-process, `test_gemma4_cuda.c`, `SP_XBAR_PAGE_GATE=1`): legacy full-cache decode vs the paged decode → **token-identical, `diffs[4..16)=0`**, both `2 10 100 1000 497 564 101 101 236855 45518 5015 101 101 100 236751 236751`, `TEST_EXIT=0`, no leak. **This is the write-path ∘ read-path composition running as one live loop — the model's entire history lived on disk and fed attention bit-exactly.** **SCOPE — what this earns and what it does NOT:** it earns the recall READ off disk during live generation. It does NOT shrink VRAM: page-in reconstructs `[0,pos)` into the full-size live cache each step (no `sink+W` allocation), and a *global* layer attends every position so it structurally cannot drop below `ctx` without *sparse* recall — that's the router (P3.2-b-2 / the P2.b §3q two-stage door), a policy layer above this substrate. Only SWA (windowed) owners can shrink to `W` on the substrate alone. **PERF:** like P3.2-a, the per-step synchronous page-in/spill serializes the decode (gate-only cost; restricted to the P=16 DEC prompt — `O(ctx²)` disk reads make the long velocity decode impractical until the router makes recall sparse). Engine `cuda_forward.cu` (page-in + poison, behind `SP_XBAR_PAGE`, byte-inert off), built VS2022/VS18 host.

**G-P3-R2.b-2a RUN-RECORD — SWA ring shrink BIT-EXACT GREEN (2026-06-12, real 12B). THE FIRST REAL VRAM WIN.** The framing refinement that defined the cut: gemma's SWA is a *pure sliding window with no attention sinks* (`k_attn_decode_win` masks `[max(0,pos-W+1), pos]`), so a SWA layer's window is ALWAYS the most-recent `W` positions — all live, *nothing to page*. The correct shrink is a **`W`-slot ring**, not the two-source-with-page-in kernel (that's the globals' job, b-2b). Implementation: SWA owners (`L<kvfs`, `!global`) allocate `Wring=min(W,P)` slots instead of `P`; the live write goes to `slot = pos % Wring` (overwriting the position that just left the window — eviction for free); a new `k_attn_decode_ring` kernel reads the window in **position order** — logical index `j` → ring slot `(s0+j) % Wring` — so the scores, the single-thread max, the exp-sum, and the V-weighted sum execute in byte-identical order to `k_attn_decode_win` over a full cache (fp non-associativity defeated by matching the reduction order, not just the key set). Globals are untouched (full `P`; they attend all positions). Flags `SP_XBAR_SWA_RING` (enable) + `SP_XBAR_SWA_W=<w>` (window override, applies to BOTH the full-cache baseline and the ring so the gate exercises wrap+eviction cheaply). **GATE** (in-engine, `SP_XBAR_SWA_GATE=1`): full-cache decode at window 4 vs ring-of-4 decode → **token-identical, `diffs[4..16)=0`** (both `2 10 100 1000 497 236751 236751 236777 8455 604 …`; this sequence differs from the window-1024 run *because* the window is 4 — the gate is ring==full-cache *at the same window*, and both ran 4), `TEST_EXIT=0`, no leak, P=16 wraps the 4-slot ring 3×. **WHY THIS IS THE WIN:** the 40 SWA owners carry kvd=2048 (vs the 8 globals' kvd=512), so SWA is the **dominant** cache term — at 32k it alone is ~21 GB of the linear-in-context cache. Capping it at `W` makes that term **constant** (≈0.67 GB at W=1024), leaving only the 8 small global layers scaling with context (~1 GB at 32k) — the remaining context-linear term that **P3.2-b-2b** (global sparse top-k recall via the P2.b §3q router) collapses. **SCOPE:** bit-exact shrink on **40 of 48 layers (83%)**, substrate-only, no router, no disk. Engine `cuda_forward.cu` (`k_attn_decode_ring` + ring alloc/write/dispatch, behind the SWA flags, byte-inert off), built VS2022/VS18 host. **NEXT = P3.2-b-2b the global shrink** (sparse recall router on the 8 globals — where the last context-linear term dies and VRAM fully decouples from context).

## 4. Risks

1. **CUDA-graph capture vs per-step ring branches.** The ring needs host work (or at minimum data-dependent indices) inside the step — incompatible with the captured graph. Precedent: the X-R1/XBAR seam already declines the graph when knobs are set (`use_graph = … && !xbar_on`, cuda_forward.cu:1840). **Accepted for v0:** `SP_ARM_*` set ⇒ per-step path, graph declines, banner says so; knobs-off must re-green BOTH paths bit-exact. Graph re-capture with ring on (e.g. fixed-budget gather kernels with device-resident indices) is the deferred perf stage.
2. **VRAM budget on the 2060-12GB.** Weights ≈ 6.4 GB (OK_Q4B per-32) ⇒ ~5 GB headroom. Jagged K+V cache = `2·48·512·4·P` = 196,608·P B: **384 MiB @ P=2k, 768 MiB @ 4k, 1.5 GiB @ 8k** — fits with room at every gate point; P=32k (6 GiB) is out of v0 scope and is exactly what P3.2b's Ring-1 shrink is for. projk stays host-side (≤ 176 MiB RAM, table above) — VRAM-neutral in v0.
3. **Host-device sync per step.** ~480 KiB/step D2H + syncs on the router lane, ~192 KiB/step on the spill lane (owner K+V) — low-ms against 38.3 ms/step; single-digit-% tax, diagnostic-lane precedent (the XBAR ranks telemetry already syncs per step, cuda_forward.cu:2293-2296). If measured worse than ~10%, batch the D2H per step (one staging buffer, one copy), don't redesign.
4. **#115-closed dependency (enabling, not blocking).** Tokenizer parity 5432/5432 both lanes + ROUNDTRIP 60/60 means P3.1b/P3.2b needles run on REAL prompts, not fixtures. Run-prep: 12B text-in needs the gold-blob `--tok-only` regen first (night-shift 06-10 note).
5. **V-less globals on the 12B (corrects §3b finding #5's resolution).** The audit declared "no V=K aliasing — SP projects V via attn_v for both classes"; that holds for the E2B-class artifact but NOT the 12B: dense gemma-4 globals ship no `attn_v`, and both forwards implement the V-less fallback — V = raw K projection, weightless-normed, never roped (gemma4.c:179-187; cuda_forward.cu:2148-2149, also 1878-1879/1953-1954; CONTRACT-XBAR-P1 §1 table). **Episode format is unaffected** (V blocks store the minted V bytes whatever their provenance, and replay injects K+V as a pair), but the manifest carries `vless` per layer and any future re-mint/re-rope tooling must NOT re-derive V from post-norm K on globals. No new gate; a law line so nobody re-trips the eta-5b confusion.
6. **Mixed-artifact gate drift.** G-P3-SHARED greens on the E2B; the 12B never exercises owner-indirection (all owners). Stated plainly: a 12B-only green is NOT shared-KV-ready, and an E2B-only green is NOT 12B-capacity-ready. Closure requires the per-stage artifact assignments in §2 as written.
