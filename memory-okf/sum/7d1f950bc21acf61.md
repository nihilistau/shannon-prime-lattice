# MTP CORRECTION: daemon spec_step verifies SEQUENTIALLY (no speedup); real gap = a BATCHED target-verify verb, not the draft source

spec.rs spec_step verifies one target decode_step per accepted token (slower than plain decode). Not the accelerating version (sp_toks.c used a batched qwen3_forward verify). Real MTP prerequisite = batched target-verify verb in the CUDA kvdecode path (K tokens->K logits, accept prefix, rewind). Draft source/VRAM come after. Don't wire the sequential spec_step (non-functional). Correct CONTRACT-C4-SPECDECODE.
