BATCH PREFILL (#41, CONTRACT-BATCH-PREFILL.md, recon done 2026-07-03): the batched multi-position forward ALREADY EXISTS = gemma4_cuda_probe (cuda_forward.cu ~1791): n_tok-wide gemm_w_lift per weight, k_rmsnorm<<<n_tok>>>, batched k_rope, batched k_attn, AltUp/PLE precompute. DON'T REBUILD IT. gemm_w_lift (~5512) HANDLES the packed OK_Q4B 12B weights (bscale->gemm_w, else k_codes_f32 dequant->cublas gemm->k_scale_rows). The ONLY gap for a resident batched prefill: (a) it sinks K/V to throwaway Kst[L]/Vst[L] (~2001-2007) not s->dKc[L]/dVc[L]; (b) the probe FULL head needs g_w.embd (f32) which the 12B lacks (packed only) so it self-disables - SKIP the head, prefill only needs K/V + last-pos logits which the caller gets from the PACKED decode_step(last). Design: gemma4_kv_prefill_batched writes dk/dv to dKc[L]/dVc[L] at [0,n) (full-cache slot==pos so contiguous), set device+host dpos=n, stop before head.
