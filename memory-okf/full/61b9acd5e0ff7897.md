# TELE-14 — Standalone Sovereign Native Cross-Family Delegate (DONE)

**Status:** GREEN (G-TELEPATHY-NATIVE). Engine commit `2f57520`. Default-off.

## What it is
The daemon executes a **completely sovereign, native, zero-Python** cross-family delegation:
it loads the qwen2.5-coder sp-model in its own L1 session and answers a clean-text task
entirely in-engine. This is "Path A" (standalone) — deliberately NOT co-resident with the
live 12B serving, so it never touches the `g_w` CUDA global (no byte-exact-12B regression risk).

## How it works (DO NOT REBUILD)
`SP_TELEPATHY_NATIVE=1` (+ `SP_TELEPATHY_CODER_MODEL`, `SP_TELEPATHY_CODER_TOK`,
optional `SP_TELEPATHY_TASK`/`SP_TELEPATHY_NGEN`/`SP_TELEPATHY_EOS`) →
`main.rs` dispatch → `eagle_accept::run_telepathy_native(model, tok)`:
1. `SpModel::load(coder.sp-model, coder.sp-tokenizer)`; `arch_info()` → `vocab_size`.
2. `SptbTokenizer::build(&model, arch.arch_id, tok)`; encode task via `apply_template_ids([user: task])`.
3. `SpSession::create(&model, cancel)` — plain `sp_session_create` (CPU L1; the CUDA backend is
   registered SEPARATELY in `daemon.rs`, not here).
4. `session.prefill_chunk(&prompt, &mut logits)` → last-token logits → argmax.
5. loop `n_gen`: `session.decode_step(tok, &mut logits)` → argmax (O(n) KV-resident); break on eos.
6. detok via `tok.decode_token(id)`.
This is the SAME host-CPU decode pattern the `sp_memo_*` bins use.

## Result

0.8 tok/s) -> "Here's a Python function that reverses a string: ```python def reverse_string(input_string): ..."`
HF parity inherited from the top-1-lossless transcode gate (identical-token argmax == oracle).

## GOTCHAS banked (cost real time — do not repeat)
1. **CUDA `qwen3_decode_cuda` and `qwen3_forward_cuda` are STRICT `SP_ARCH_QWEN3` (==0) only.**
   The qwen2.5 coder loads as `SP_ARCH_QWEN25` (==2) → both reject it (`return -1`).
   There is NO CUDA QWEN25 decode path. (Enum: QWEN3=0, GEMMA3=1, QWEN25=2, GEMMA4=3, QWEN36=4.)
2. **`qwen3_generate_kv` called on the daemon's wire_cuda `SpSession` SEGFAULTs (0xC0000005).**
   The CUDA-capable session releases host weights after GPU upload; the CPU reference forward then
   dereferences freed pointers. Do not call the bare CPU forward on a CUDA session's model.
3. **The correct host-CPU decode is the L1 wrapper surface:** `SpSession::{prefill_chunk, decode_step}`
   with a `vec![0f32; arch.vocab_size]` logits buffer.

## Why CPU is also the clean co-residency answer (Path B note)
CPU L1 decode uses host memory, NOT the CUDA `g_w` global → it can run alongside a resident GPU 12B
with zero contention. So the "live co-resident delegate" doesn't need the risky `g_w` per-model
refactor — a CPU L1 coder session is the safe co-residency route (speed cost: ~0.8 tok/s for 0.5B).
