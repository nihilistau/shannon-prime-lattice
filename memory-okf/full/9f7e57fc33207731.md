ï»¿PowerShell cd / Set-Location changes the PROVIDER location but NOT the .NET process CWD. So [System.IO.File]::ReadAllText/WriteAllText with a RELATIVE path resolve against C:\Users\Knack (the process CWD), NOT the cd-d dir - they silently read/write the wrong file or throw FileNotFound. FIX: always pass ABSOLUTE paths to [IO.File] calls. (Select-String, git, python respect the shell cwd; only .NET static IO methods do not.) Cost 3 failed routes.rs edit attempts.
